# Spec Mapper AI

Вторая ступень после `spec-extracting-ai`: принимает готовый JSON от 1С/бота или
получает его по UUID извлечения, подбирает **Top-5** через shared-embedding и Qdrant.
Web позволяет искать по всему справочнику, перевыбирать позицию, явно оставлять её
без соответствия и утверждать неизменяемый итог для 1С. Доступны JSON/Excel.
Excel после утверждения использует локальный шаблон Extracting A:S и шесть полей
сопоставления T:Y; прежний адрес `result.xlsx` сохранён.
Регистрации, обучения моделей и облачных AI API нет.

## Настройки

Обычные настройки — в `.env.example` или окружении команды. Pydantic и Compose:
**окружение → `.env` → `.env.example` → defaults**. `.env` содержит секреты и необходимые частные overrides.
Первый запуск атомарно создаёт отсутствующие `DATABASE_PASSWORD`, `RABBITMQ_PASSWORD`,
`SESSION_SECRET`, `CATALOG_ADMIN_KEY`, `ONEC_CATALOG_WEBHOOK_KEY` и `API_KEYS`
с отдельными ключами `onec`/`telegram`.
Существующие значения, включая прежний `API_KEY`, сохраняются; права Linux 0600.
Пользователи web не создаются: автоматически готовятся DB/RabbitMQ credentials и cookie-сессии.

Для polling добавьте в `.env` **существующий** ключ извлечения:

```dotenv
EXTRACTING_API_KEY=<ключ spec-extracting-ai, владеющий исходным заданием>
```

Для прямого JSON upstream-ключ не нужен. Ключи mapper и extracting различаются;
секрет shared-embedding не требуется. Не помещайте API-ключи в браузерный JavaScript.

## Развёртывание

Linux: Docker Engine/Compose **2.24+**, `uv`, доступ к Docker и работающие
RabbitMQ/shared-embedding в `ai-shared`. Для локального источника положите XML в `data/`;
для HTTP настройте подтверждённый безопасный источник 1С. Затем:

```bash
bash scripts/up.sh
```

Команда проверяет окружение/порты, готовит секреты и выделенные RabbitMQ user/vhost,
собирает контейнеры, применяет миграции, импортирует каталог с прогрессом и ждёт
реальной готовности. Логи видны. Повторный запуск сохраняет данные и volumes.
Адрес: **http://192.168.55.3:8087/**; API-документация: **/docs** без внешнего CDN.
Параметры `APP_BIND`, `APP_PORT`, `APP_PUBLIC_BASE_URL` — в открытой конфигурации.
Защищённый операторский gateway доступен только на loopback сервера
`127.0.0.1:8088` (`OPERATOR_PORT`); общий web/API остаётся на 8087.
DB/Qdrant наружу не публикуются. Доступ — LAN/VPN; публикация в интернет требует
отдельного HTTPS reverse proxy и сетевой политики.

В текущем XML — **62 052** разрешённые активные позиции. Конфликтующие коды целиком
карантинируются. GUID 1С отсутствует: внутренний UUID и `onec_guid=null` различаются.
Первый импорт имеет отдельный предел 24 часа и возобновляемые checkpoints;
неизменённые позиции повторно не векторизуются. Ежедневная полная сверка выключена
по умолчанию, время 15:00 UTC. Поддержаны полный JSON/XML по HTTP и durable webhook 1С.
XML не обязателен для HTTP bootstrap или запуска с проверенным сохранённым каталогом.
`CATALOG_SOURCE_TYPE=local_xml` остаётся bootstrap fallback; в установленном сервисе
источник HTTP сохраняет оператор через GUI в PostgreSQL. Изменение env его не подменяет.
12.11.2026 владелец проверил `/export`, `/items` и `/items/batch` с Ubuntu,
доступ к 1С также подтверждён из API-контейнера Mapper.
Для этого адреса разрешён Basic с непустым username и пустым паролем при явном
`ONEC_CATALOG_ALLOW_HTTP=true` и точном allowlist. По умолчанию HTTP запрещён;
Bearer требует HTTPS. После установки исправления выполните
[настройку, probe и первый импорт](docs/INTEGRATION_1C.md#подключение-подтверждённого-http-api).
Реальная доставка webhook из 1С ещё не проверена.

## Проверки

```powershell
.\ops\check-quality.ps1
```

```bash
bash scripts/test.sh          # Ruff, Python, Node, браузер
bash scripts/test.sh --live   # после up.sh, дополнительно реальные зависимости/API
```

`up.sh` разворачивает сервис, применяет миграции и импортирует сохранённый источник
каталога; это основная команда полного запуска. Обычный `test.sh` запускает собственные
временные HTTP-сервисы/SQLite, поэтому работает до или после развёртывания.
Проверку перед обновлением рекомендуем для поиска регрессий до пересоздания контейнеров.
Только `--live` требует уже поднятых реальных зависимостей.

Первый запуск устанавливает Chromium; на минимальном Linux заранее:
`uv run playwright install --with-deps chromium`. Браузерные offline-тесты явно
подменяют AI/broker; live-тесты используют настоящие сервисы.

## Главная и расписание

На `/` — реальные KPI, справочник, задания и статусы; таблица подбора — `/mapping`.
Настройки синхронизации сохраняются в PostgreSQL: по умолчанию выключено, 15:00 UTC.
Ручной импорт XML сохранён. Настройки меняет только оператор: замените SSH-логин своим,
откройте туннель и страницу `http://localhost:18087/operator`:

```powershell
ssh -N -L 18087:127.0.0.1:8088 ВАШ_ЛОГИН@192.168.55.3
```

Нажмите «Получить одноразовый код», введите выданный код и начните сессию.
После доверенного входа инструкция SSH скрывается. Прежний CLI ticket остаётся
резервным способом входа. V4 добавляет миграцию 0004 и отдельный webhook secret.
Регистрации пользователей нет; чужие документы оператору не открываются.
«Обновить сейчас» доступно всем для настроенного и подтверждённого HTTP-источника
1С, с общим интервалом 60 секунд; локальный XML через UI обновляет оператор.
Общее утверждение подтверждает текущие выборы/null всех строк сразу, крестик
очищает только ошибочное соответствие. Фавикон выполнен в стиле логотипа.
Подключение подтверждённого HTTP API включается владельцем отдельно. Пароли/token задаются только на сервере через
Pydantic Settings; браузер видит лишь credential reference и признак наличия.
