# Техническое задание

Сервис локально сопоставляет строки спецификаций проектной и рабочей документации
с актуальной номенклатурой 1С. Внешние зависимости принадлежат shared инфраструктуре:
`shared-embedding` и RabbitMQ; PostgreSQL и Qdrant принадлежат этому проекту.
Никакой регистрации, админ-панели, обучения или облачных AI API.

## Вход и результат

Основной вход — UUID задания `spec-extracting-ai`. Сервер с `X-API-Key` ограниченно
опрашивает `/api/v1/extractions/{job_id}` и после `completed` либо
`completed_with_warnings` получает `/result.json`. `failed`, `cancelled`, 404, 410,
ошибки авторизации, сети и timeout различаются кодами. Частичный JSON не принимается.

Готовый документ имеет только `items`, каждая строка — только строковые `Caption`,
`Units`, `Quantity`, `UserComment1`, `Pages`. Значения, порядок, пробелы и дубли
сохраняются. Результаты хранятся отдельно по owner, source UUID, индексу строки,
hash исходника и версии каталога. Готовый JSON можно импортировать независимо.

## Справочник

Фактическая схема XML: `СправочникНоменклатура/Позиция`, атрибут `код`, поля
`Наименование`, `НаименованиеПолное`, `Артикул`, `Группа`, `ГруппаВерхняя`,
`ВидНоменклатуры`, `ТипНоменклатуры`, `ЕдиницаИзмерения`, `Производитель`, `Марка`,
`ПометкаУдаления`. XSD не предоставлена. Ссылок GUID в предоставленной выгрузке нет.

Парсер потоковый, запрещает DTD/entities/XXE, ограничивает суммарный размер,
проверяет корень, обязательные значения, UUID при наличии и повторные GUID.
Удалённые позиции исключаются. Конфликтующие коды полностью карантинируются
по явному решению владельца; warning доступен через API и web. Пустой справочник — ошибка.
Код используется для стабильного внутреннего UUID; настоящий GUID хранится отдельно.

Общий порт `CatalogSource` и `SynchronizeCatalogUseCase` позволяют добавить адаптер
1С после получения API/авторизации. Daily sync выключен по умолчанию; включение
`CATALOG_DAILY_SYNC=true` запускает периодический импорт локальных XML. Неизменившиеся
позиции повторно не векторизуются. Фиксируются last_successful_sync и последняя ошибка;
PostgreSQL advisory lock исключает параллельную публикацию.

## Подбор и ревью

Нормализация сохраняет технические характеристики. Embedding и Qdrant Top-K батчатся,
metadata загружается пачкой. Детерминированное ранжирование учитывает единицы,
DN/PN, мощность, давление, расход, напор, марку и подтверждённые признаки.
Несовместимые единицы/параметры и неполные сведения переводят строку в ревью.
Cosine-score — мера сходства, не вероятность. Алгоритм имеет явную версию;
начальные консервативные пороги не объявляются статистически откалиброванными.

Светлый интерфейс следует `renders/`: статус, totals, таблица исходных и выбранных
полей, Top-K в боковой панели, поиск по всему каталогу, ручной выбор или явный отказ.
Фильтры, поиск и пагинация не меняют общие totals. Сохранение атомарно; reload
восстанавливает выбор. Ручное действие не обучает модель и не меняет индекс.
JSON/Excel сохраняют исходную пятёрку; оригинал выгружается отдельно.

## Надёжность и безопасность

Состояния: queued → polling → fetching → matching → complete/ready_for_review или failed.
Техническое завершение допускает пустые/неоднозначные кандидаты. Idempotency-Key
дедуплицируется по owner; другой payload даёт 409. PostgreSQL outbox, durable RabbitMQ,
lease/fencing и checkpoints обеспечивают at-least-once обработку после restart.

Временные документы/результаты доступны час после terminal состояния; незавершённое
задание — до часа с создания. После TTL API сразу запрещает доступ, worker удаляет
записи. Каталог, XML и persistent volumes не удаляются с заданиями.
Web использует HttpOnly/SameSite cookie, CSRF и точный Origin. Интеграционный ключ
и отдельный credential импорта не передаются браузеру. Ограничены загрузка, запросы,
polling, concurrency, retry и логи. Открывается только web/API, порт 8083 запрещён.

## Приёмка

На подготовленном сервере `bash scripts/up.sh` запускает собственный стек, применяет
миграции и импортирует реальный XML. По upstream job UUID получаются все исходные
строки, предлагаются Top-K, сохраняется ручной выбор и скачиваются корректные отчёты.
Проверяются повторная доставка, restart, TTL, owner isolation, смена каталога,
count/alias rollback и недоступность shared зависимостей. Offline, browser и live
результаты в отчёте различаются. Коммиты и push выполняет только владелец.
